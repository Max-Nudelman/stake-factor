# Stake Factor, in the browser

An interactive version of the bettor segmentation project. It simulates accounts
betting into a real market layer, then measures how many settled bets it takes to
tell a sharp from a lucky recreational one, and what acting on that costs.

The finding it is built around: **closing line value separates adverse accounts at
AUC 0.98 after five bets. Realized profit and loss never clears 0.62, even after a
hundred.** Detection is not the constraint. Threshold choice is.

## Status

Builds clean and runs. Verified 2026-09-10: `npm run lint` reports no warnings or
errors, `npm run build` type checks and compiles with none, and the simulation was
driven in a browser end to end. A 2,000 account run placed 236,145 bets in 0.2
seconds and reproduced the finding: sharps came back at +7.58% mean closing line
value against a published +7.61%, and AUC 0.974 after five bets against a published
0.981.

Node came from conda rather than Homebrew, which is the path of least resistance on
this machine:

```bash
conda install -c conda-forge nodejs -y
```

Then:

```bash
npm install && npm run dev
```

The model logic is separately verified against the published run by
`scripts/verify_port.py` in the analysis repo, which replicates the port's structure
in Python. Mean CLV matches to four decimals on all five segments.

## What the browser actually runs

`lib/simulate.ts` and `lib/detect.ts` are ports of `src/simulate.py` and
`src/detect.py` from the analysis repo. The page runs the model rather than
replaying a recording, which is why the controls change the answer.

The one thing the browser cannot do is reproduce numpy's random stream, so a live
run lands near the published numbers rather than on them. Both are shown, labelled,
side by side. Nothing on the page pretends they are the same run.

## The argument, in twelve figures

Figures 1 to 4 are **real market data** and carry the part of the argument simulation
cannot. Figures 5 to 12 simulate accounts on top of that market.

| # | Figure | What it establishes |
|---|---|---|
| 1 | Calibration, open vs close | Both prices are well calibrated; the close is better by a paired t of 6.29, bootstrap 95% CI [0.0017, 0.0032] |
| 2 | Accuracy gain by line movement | **The mechanism.** The close beats the open only where the price moved; the quiet quartiles show nothing |
| 3 | Overround and Brier by league | Margin varies more than accuracy. Thin leagues are expensive, not mispriced |
| 4 | Calibration against sampling noise | Every league between 0.68 and 1.26. Nobody beats the close |
| 5 | Segment economics | The book holds ~5% everywhere except sharps |
| 6 | CLV distribution by archetype | Sharps do not overlap anybody |
| 7 | Return distribution by archetype | The same accounts are indistinguishable on realized profit |
| 8 | Detection curve | CLV near perfect at five bets; profit never arrives |
| 9 | ROC at five bets | What the AUC summarises: catch nearly all sharps at a small false positive rate |
| 10 | Stability across 12 runs | The ranges never touch, so the gap is not one lucky seed |
| 11 | Policy cost by threshold | Cutting too widely costs more than the sharps take |
| 12 | CLV rank by archetype | Semi sharps rank high and are profitable. The correction that reshaped the project |

Figures 5 to 12 recompute live from whatever run is on screen, so changing the account
count or the seed changes them.

Section 5 closes with the half of the argument the cost model cannot price: why restricting
a sharp carries reputational risk that does not appear in any of the figures above it. Both
halves point at the same conclusion, a conservative threshold rather than an aggressive one.

## Layout

An editorial case-study structure. Sentences live in a 620px centred reading column;
charts and tables break out to the full 1120px against it. Sections open with a centred
number and title. That contrast between a narrow measure and full-width figures is what
makes a page this long navigable.

## Data

| file | what it is | generated by |
|---|---|---|
| `web/data/market-layer.json` | 13,638 matches with complete average opening and closing 1X2 prices, six leagues, 2019 to 2025 | `src/export_market.py` |
| `web/data/market-figures.json` | Figures 1 to 4: the league SQL run unchanged, plus the open versus close test | `src/export_market_figures.py` |
| `web/data/published-run.json` | The 4,000 account numpy run: detection curve, policy costs, segments, CLV histogram | `src/export_web.py` |

All three are regenerated from DuckDB, so the site and the analysis cannot drift apart.
From the repository root:

```bash
python3 src/export_market.py && python3 src/export_web.py && python3 src/export_market_figures.py
cp outputs/market-layer.json outputs/market-figures.json web/data/
cp outputs/stakefactor-web.json web/data/published-run.json
```

`scripts/verify_port.py` then re-checks that the TypeScript port still reproduces the
published run.

Odds are stored as integer hundredths and results as one character per match, which is
what keeps the market layer at 335 KB. It ships to the client on purpose: the simulation
runs in the browser, so the prices have to be there.

## Design

`DESIGN.md` is the source of truth and was written before any component. Two
additions were made to it during this build rather than improvised in a component:

- **Data series tokens.** `series-1` and `series-2`, taken unchanged from the
  validated categorical palette in the `dataviz` skill. Brand blue is deliberately
  excluded, because blue means "you can click this" everywhere else here.
- **Polarity is position.** Gains and losses are read against a zero baseline, not
  from colour, so the reserved status colours stay reserved.

Charts are hand written SVG. No chart library, consistent with the rest of the
portfolio.

## Publishing

Two deployments, one codebase. They differ only in `basePath`, because GitHub Pages
serves a project repo from a subdirectory and the exported HTML has to know its own
prefix or every asset 404s.

| Target | Command | Lands at | Copy `out/` to |
|---|---|---|---|
| Portfolio demo | `npm run build:portfolio` | `max-nudelman.github.io/demos/stake-factor/` | `~/Desktop/max-portfolio/demos/stake-factor/` |
| Standalone site | `npm run build:standalone` | `max-nudelman.github.io/stake-factor/` | `../docs/` |

**Stop the dev server before either build.** `next dev` and `next build` fight over
`.next`, and the failure is silent: the export comes out with only a 404 page.

**`.nojekyll` is required in both targets.** GitHub Pages runs Jekyll by default and
Jekyll ignores any directory starting with an underscore, which would delete the whole
`_next` folder and serve a blank page. The portfolio already has one at its root; the
standalone build writes one into `docs/`.

**The portfolio copy is canonical.** Both builds emit
`<link rel="canonical" href="https://max-nudelman.github.io/demos/stake-factor/">`, so
the pair is not treated as duplicated content. Change that in `app/layout.tsx` if the
standalone site ever becomes the primary one.

To enable the standalone site: in the `stake-factor` repo on GitHub, Settings, Pages,
set Source to the `main` branch and the `/docs` folder.
